# 調査依頼書: 点群の超高速接続探索（Connected Component Labeling / Region Growing）

## 背景と課題
現在、Unity (C#) にて点群の空間近接接続探索（選択された点から指定半径 `localRadius` 以内の点を連鎖的に選択する機能）を実装していますが、Octreeを用いた探索を点ごとに再帰的に呼び出す方式（BFS）となっており、最大20万点以上の選択を行う際に非常に動作が重くなるという問題があります。

## 調査依頼内容
以下の条件を満たす、点群の接続探索（Region Growing, Connected Component Labeling）を極めて効率的に行うための手法・アルゴリズムを検索・調査してください。

1. **極めて効率的であること**: 
   - 数百万点の点群に対しても、数秒以内またはリアルタイムに近い速度で処理できる手法。
   - Spatial Hashing（ボクセルグリッド）＋ BFS、あるいは Voxel-based Union-Find などの高速化手法を重点的に調査してください。
2. **投入実績があること**:
   - PCL (Point Cloud Library) や CloudCompare などで採用されているような実績のある手法。
   - 研究段階を脱していない（不安定な）アルゴリズムは避けること。
3. **C# / Unity に適した実装方針**:
   - お手本となるようなGit上のC#コードやアルゴリズム解説があれば優先して取得してください。
4. **調査結果の出力**:
   - 調査結果、参考にした手法、および具体的なC#での実装方針（アルゴリズムのフロー）を `docs/research/efficient_pointcloud_ccl.md` にMarkdown形式で出力してください。
   - 既存のファイルを直接変更しないでください。

## 出力要件
- 検索MCP、GitHub検索、論文APIなどを多用し、具体的に「どのようなデータ構造とループ処理にすればOctree探索のオーバーヘッドを削れるか」の最小実装案を含めること。
