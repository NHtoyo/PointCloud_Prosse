# UI/UX監査

## 静的確認

- 主なUIはUnity IMGUI (`OnGUI`) を使用します。
- 左右パネルは画面幅の25%を基準に最大460px、中央pipelineは左右の幅を差し引いて配置する実装です。
- 計測・茎径・進捗の独立パネルと、スクロール領域があります。
- UIヒットテストは画面サイズ由来の範囲判定と各パネルの専用判定を組み合わせています。
- 長い処理に使う`PointCloudProgressManager`はキャンセル・失敗詳細を持ちます。PLY読込とC2Cに進捗/キャンセルを接続しました。

## 発見事項

画面幅が小さくなるとパネルは狭くなりますが、レイヤー編集などには固定幅の入力欄・ボタンが残っています。したがって、狭いGame Viewでは横はみ出し・文字の省略・押しづらさの可能性があります。ヒットテストにも固定高さの範囲が残るため、ウィンドウサイズ変更後の入力ブロックを目視確認してください。

## 実施していない確認

本監査ではUnity Game Viewを操作・撮影できませんでした。以下はすべて`NOT_RUN`です。

- 800x600、1280x720、1920x1080での表示・操作
- 日本語フォント・長いファイル名・エラー詳細の折返し
- スクロール、モーダル、ボタンを重ねた時のクリック遮断
- マウスホイールと点群ズーム、中央クリックと計測操作の競合
- 長時間処理中のキャンセル・エラー復帰の画面確認

未確認のUI変更をコードへ加えていません。画像付きの確認結果を得てから、レイアウトとヒット領域を一緒に調整してください。
